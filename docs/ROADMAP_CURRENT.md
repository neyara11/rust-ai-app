# ECO AIOps — актуальный roadmap

- **Дата:** 2026-11-19
- **База:** 0.4.3
- **Статус:** актуальный. Исторический план — `docs/ROADMAP.md`; подробное
  состояние и backlog — `HANDOFF.md` §6/§11; corporate-поставка —
  `docs/CORPORATE_DEPLOYMENT.md` (здесь не рассматривается).
- **Обозначения:** `сделано` — есть в коде; `частично` — есть часть или закрыто
  иначе; `открыто` — не реализовано; `снято` — исключено из плана.

P0-блокеров нет: прототип работоспособен. Ниже — P1 (до расширенной эксплуатации)
и P2 (продукт/удобство).

## 1. Снимок на 2026-11-19

### Сделано

- Tauri 2 + WebView2: офлайн-шрифты, CSP, preflight WebView2 с понятным сообщением,
  single-instance lock на профиль.
- Движок opencode: один процесс на приложение, Job Object с `KILL_ON_JOB_CLOSE`,
  безопасное снятие осиротевших движков, офлайн-старт без npm (seed lockfile),
  `engine.stderr.log`.
- Чат: markdown (заголовки/списки/код/таблицы/ссылки), подсветка, Mermaid и Chart.js,
  экспорт SVG/PNG, token-контекст-чип с кэшем, картинки и кэш вложений,
  drag-and-drop и вставка из буфера, поиск и переименование сессий, watchdog,
  SSE-reconnect, «Повторить» для прерванного хода.
- Инструменты: HTTP-MCP, per-app MCP/secrets, probe MCP, permissions/подтверждения,
  таймауты/лимиты вывода/kill дерева, артефакты >64 КиБ и
  `artifact_list`/`artifact_search`/`artifact_read`.
- Пакеты: подпись, hashes, allowlist/CRL, anchor и ротация ключей,
  install/update/rollback/история версий, `eco-pack`, `office-writer` (docx/xlsx,
  нативные графики), `agent-repacker`, `doc-lookup`.
- Идентичность и аудит: короткоживущие токены, отзыв, локальный `audit/<app>.jsonl`.
- Поставка: NSIS `perMachine`, WebView2 `offlineInstaller`, dev-подпись
  (production Authenticode — открыто, P1), вендоринг движка по
  `tools/engine.lock.json`.

### Частично / закрыто иначе

- **Word/Excel** — реализовано в пакете `office-writer`; платформенного экспорта
  ответа/диалога нет по дизайну (конвертер принадлежит пакету).
- **draw.io** — отдельного `.drawio` нет; `office-writer` пишет `.mmd` по одной
  схеме, draw.io 31+ его импортирует, draw.io 30 — нет. Нативный `.drawio` и
  многолистовая книга — только если нужна совместимость с 30/один файл на сессию.
- **Настройки приложения** — MCP/секреты/рабочая папка/UI есть; профилей моделей и
  выбора модели на уровне приложения нет.
- **Token-чип** — есть; live-usage во время стрима не обновляет его (обновление по
  финалу/истории).
- **Аудит** — локальный JSONL и tail в настройках приложения; нет ротации,
  полноценного viewer, фильтров и экспорта.
- **Артефакты** — панель, поиск и экспорт есть; политика хранения только в конфиге,
  полноценного предпросмотра дампов нет.

### Снято

- **Python-инструменты** (runtime/venv/wheelhouse/PyInstaller-кэш) — авторы собирают
  exe сами (например, PyInstaller), часть библиотек перешла на Rust; платформа
  запускает только готовые `bin/*.exe` из подписанного пакета.
- **MCP stdio** — не требуется; поддерживается только HTTP-MCP.
- **Экспорт диалога в `.md`** — по текущему дизайну не требуется.
- **OS-песочница** — для прототипа не внедряется (risk-accept). Если возвращать:
  сначала `bin/*.exe`, затем движок; при sandbox движка MCP-прокси наследует
  контейнер, нужен ACL на `sessions`/`audit`/workspace или вынос прокси, иначе
  `artifact_*` и запись дампов/аудита блокируются.

## 2. Открытые задачи

### P1 — до расширенной эксплуатации

| # | Задача | Зачем | Критерий готовности |
|---|---|---|---|
| 1 | Применять `profile.max_steps`, добавить лимит tool-call на ход, параллелизм MCP и rate limit | агент не должен зацикливаться и заваливать движок | лимиты манифеста действуют; превышение даёт понятную ошибку и аудит |
| 2 | Ротация аудита + чтение tail + мьютекс на запись | журнал растёт без ограничений | ротация по размеру/дате, tail не читает весь файл, параллельные записи не теряются |
| 3 | Профили моделей и выбор модели на уровне приложения | разные endpoint/model/ключи и capabilities под задачи | 2 профиля, per-app выбор, переключение с рестартом движка, ключи изолированы |
| 4 | Канал обновления платформы/движка/пакетов + production-подпись, CI, SBOM/SAST/SCA, чистая установка | поставить и обновлять без ручных действий | подпись УЦ, N-1/откат платформы, проверка хеша `opencode.exe`, установка на чистой машине |
| 5 | Матрица совместимости «платформа × пакет» | предсказуемое тиражирование | проверяются `min_shell_version`/capabilities/поля, матрица тестов и отказ с адресной ошибкой |

## 3. Рекомендуемый порядок

1. Лимиты (`max_steps`, tool-call, MCP/rate limit) — безопасность длинных сессий.
2. Ротация аудита и tail — эксплуатация без роста журнала.
3. Профили моделей и per-app выбор.
4. Обновления, подпись, CI/SBOM и чистая установка.
5. Матрица совместимости и кэш проверки пакетов.
6. Продуктовые P2: чат-UX, backup, i18n/a11y, audit viewer.

## 4. Что не считать пробелом

- Word/Excel — есть в `office-writer`; платформенного экспорта нет намеренно.
- draw.io — `.mmd` + draw.io 31+; нативный `.drawio` нужен только для 30.
- MCP stdio — не нужен; HTTP-MCP достаточно.
- Python-рантайм — снят; авторы собирают exe сами.
- Артефакты >64 КиБ и `artifact_*` — реализованы; sandbox только `bin/*.exe` их не
  ломает (файлы пишет/читает прокси, а не exe).
- Поиск/переименование чатов, drag-and-drop, вставка изображений, token-чип,
  MCP-probe, allowlist/токены, офлайн-npm, WebView2 preflight, single-instance —
  уже есть.
