# ECO AIOps — актуальный roadmap

- **Дата:** 2026-11-21
- **База:** 0.5.0
- **Статус:** актуальный. Исторический план — `docs/ROADMAP.md`; подробное
  состояние и backlog — `HANDOFF.md` §6/§11; corporate-поставка —
  `docs/CORPORATE_DEPLOYMENT.md` (здесь не рассматривается).
- **Обозначения:** `сделано` — есть в коде; `частично` — есть часть или закрыто
  иначе; `открыто` — не реализовано; `снято` — исключено из плана; `отложено` —
  делается только по условию.

P0/P1-блокеров нет: прототип работоспособен. Ниже — P2 (продукт/удобство).

## 1. Снимок на 2026-11-21

### Сделано

- Tauri 2 + WebView2: офлайн-шрифты, CSP, preflight WebView2 с понятным сообщением,
  single-instance lock на профиль.
- Движок opencode: один процесс на приложение, Job Object с `KILL_ON_JOB_CLOSE`,
  безопасное снятие осиротевших движков, офлайн-старт без npm (seed lockfile),
  `engine.stderr.log`.
- Чат: markdown (заголовки/списки/код/таблицы/ссылки), подсветка, Mermaid и Chart.js,
  экспорт SVG/PNG, token-контекст-чип с кэшем и live-usage из `message.updated`,
  картинки и кэш вложений, drag-and-drop и вставка из буфера, поиск и переименование
  сессий, watchdog, SSE-reconnect, закрепление сессий, edit-and-resend, regenerate,
  единые поповеры модели/reasoning/контекста, стоимость по сессии и ответу (оценка
  по ценам моделей).
- Вложения: все входящие (вставка и загрузка; image/text/PDF/docx/xlsx/pptx) копируются
  в `<workspace>/inbox` с content-addressed именем; модель получает путь, UI показывает
  чипы. Лимиты: image 4 МиБ, text 256 КиБ, документ 25 МиБ, 50 МиБ на ход; аудит
  `attachment_inbox`. `.docx` читается через `platform_read_file`; `.xlsx` — постранично
  (`sheet/offset/limit`, `next_offset`/`eof`); `.xls` не поддержан, PDF пока только
  сохраняется.
- `eco-pack` больше не запускается при старте и не мигает консолью: проверка ленивая,
  спавн идёт с `CREATE_NO_WINDOW` (P16).
- Память фактов: платформенные `memory_save/search/recent/forget` включаются per-app
  (по умолчанию выкл.), скоуп — приложение + рабочая папка; JSONL в
  `<home>/memory`, дедуп и лимиты, поиск keyword + recency; UI с поиском, пагинацией
  по 50 и удалением; при переключении простаивающий движок перезапускается.
- Capability-токен: истёкший, но не отозванный токен продлевается gateway на 12 ч
  (`token_renew`); отозванный токен или заблокированное приложение по-прежнему
  fail-closed.
- LLM: несколько провайдеров (endpoint + ключ) с наборами моделей и capabilities;
  выбор модели по умолчанию и per-app в шапке чата; переключение на ход без
  рестарта; legacy `llm_*` автоматически мигрирует в провайдера `gw`.
- Устойчивость LLM: retry/backoff для 429/5xx/таймаута (до 3 повторов), включая ошибку
  модели внутри `200 OK` (`info.error`); неудачный ход откатывается через `revert`,
  чтобы не дублировать сообщение; событие `llm_retry` в аудите. Автопереключения
  моделей нет — модель меняется вручную.
- Сжатие контекста: ручная кнопка в карточке контекста (V1
  `/session/{id}/summarize` с выбранной моделью) и авто-компакция по порогу
  заполнения окна (по умолчанию выключена, порог 80%, настраивается).
- Инструменты: HTTP-MCP, per-app MCP/secrets (endpoint/токен задаются в настройках
  приложения), probe MCP, permissions/подтверждения, таймауты/лимиты вывода/kill
  дерева, артефакты >64 КиБ и `artifact_list`/`artifact_search`/`artifact_read`.
- Пакеты: подпись, hashes, allowlist/CRL, anchor и ротация ключей,
  install/update/rollback/история версий, `eco-pack`, `office-writer` (docx/xlsx,
  нативные графики), `agent-repacker`, `doc-lookup`; проверка seal кэшируется по
  снимку метаданных (путь/размер/mtime) и digest seal — `list_apps`/`open_app` не
  пересчитывают неизменённые файлы, а установка/update/rollback по-прежнему хешируют
  всё.
- Идентичность и аудит: короткоживущие токены, отзыв, локальный `audit/<app>.jsonl`
  с ротацией (10 МиБ/24 ч, 3 файла) и межпроцессным мьютексом; tail.
- Лимиты: `profile.max_steps` → `agent.steps`, лимит tool-call на ход и в минуту в
  шлюзе (вызовы сериализованы), превышение даёт ошибку инструмента и аудит.
- Поставка: NSIS `perMachine`, WebView2 `skip` (отдельный пререквизит машины,
  Evergreen x64), dev-подпись (production Authenticode — открыто, P1), вендоринг
  движка по `tools/engine.lock.json`.

### Частично / закрыто иначе

- **Word/Excel** — реализовано в пакете `office-writer`; платформенного экспорта
  ответа/диалога нет по дизайну (конвертер принадлежит пакету).
- **draw.io** — отдельного `.drawio` нет; `office-writer` пишет `.mmd` по одной
  схеме, draw.io 31+ его импортирует, draw.io 30 — нет. Нативный `.drawio` и
  многолистовая книга — только если нужна совместимость с 30/один файл на сессию.
- **Аудит** — локальный JSONL с ротацией и tail; нет полноценного viewer, фильтров
  и экспорта.
- **Стоимость** — оценка по заданным в настройках моделей ценам; этого достаточно,
  фактическая стоимость из шлюза не требуется (шлюз может её не отдавать).

### Снято

- **Backup/restore профиля и «удалить все данные»** — не требуется: профиль это
  папка `.data`, перенос/удаление делаются штатными средствами ОС.
- **Python-инструменты** (runtime/venv/wheelhouse/PyInstaller-кэш) — авторы собирают
  exe сами (например, PyInstaller), часть библиотек перешла на Rust; платформа
  запускает только готовые `bin/*.exe` из подписанного пакета.
- **MCP stdio** — не требуется; поддерживается только HTTP-MCP.
- **Экспорт диалога в `.md`** — по текущему дизайну не требуется.
- **Политика хранения артефактов в UI и предпросмотр дампов** — не требуются:
  квоты/TTL остаются в конфиге, список дампов, grep, экспорт и очистка уже есть.
- **`eco-pack --dry-run/--reproducible`, SBOM, provenance/CI-подпись** — снято как
  оверинжиниринг: подписи пакета и `hashes` достаточно; вернуть только по явному
  требованию ИБ.
- **OS-песочница** — для прототипа не внедряется (risk-accept). Если возвращать:
  сначала `bin/*.exe`, затем движок; при sandbox движка MCP-прокси наследует
  контейнер, нужен ACL на `sessions`/`audit`/workspace или вынос прокси, иначе
  `artifact_*` и запись дампов/аудита блокируются.

## 2. Открытые задачи

### P2 — продукт и удобство

Открытых задач нет: память фактов реализована (см. «Сделано»), вложения и xlsx-пагинация
закрыты. Осталась мелкая P14 из бэклога.

### Отложено / по условию

- **Audit viewer** (фильтры, экспорт, просмотр по приложению/сессии) — отложен:
  ценности на текущем этапе нет, JSONL и tail доступны.
- **Лимит движков** (soft-cap/LRU/idle-stop) — отложен: риск задеть долгую задачу
  выше пользы; если возвращать — только idle-eviction, busy/подтверждения/долгие
  tool-вызовы не трогать, при нехватке слотов разрешать превышение.
- **Матрица совместимости «платформа × пакет»** (strict-проверки `required`/
  unknown `connection.type`/tool-полей и тест-сетка legacy↔strict) — отложена:
  не критична на текущем этапе, риск сломать существующие schema 2 пакеты выше
  пользы. `min_shell_version` и `schema_version` уже проверяются.
- **Локализация EN и доступность** (focus-trap, ARIA для диаграмм, контраст) —
  отложено.
- **Нативный `.drawio`/многолистовая книга** — только если нужна совместимость с
  draw.io 30 или один файл на сессию.
- **Observability: экспорт LLM-аудита** — когда появится целевая система.

## 3. Рекомендуемый порядок

1. Corporate-трек — отдельно, вне этого плана.
2. P14 (UA приложения) — только после согласования со шлюзом.

### Мелкие задачи (в бэклоге HANDOFF)

- **P14. `User-Agent` приложения в LLM-запросах:** `ECO-AIOps/<version>` вместо
  `opencode/<версия>`; только после согласования со шлюзом. Детали — `HANDOFF.md` P14.

### Правила для лимита движков (если вернёмся)

- Никогда не останавливать движок с активным ходом, ожиданием подтверждения или
  выполняющимся tool-вызовом (таймаут инструмента — до 2 ч).
- Останавливать только подтверждённо простаивающий движок; idle-порог задаётся и по
  умолчанию большой (например, 60 мин).
- Если свободных слотов нет, **разрешать превышение с предупреждением**, а не убивать
  занятый движок и не блокировать открытие другого приложения.
- Ручная остановка движка — отдельным действием с подтверждением.

## 4. Что не считать пробелом

- Word/Excel — есть в `office-writer`; платформенного экспорта нет намеренно.
- draw.io — `.mmd` + draw.io 31+; нативный `.drawio` нужен только для 30.
- MCP stdio — не нужен; HTTP-MCP достаточно.
- Python-рантайм — снят; авторы собирают exe сами.
- Артефакты >64 КиБ и `artifact_*` — реализованы; sandbox только `bin/*.exe` их не
  ломает (файлы пишет/читает прокси, а не exe).
- Поиск/переименование чатов, drag-and-drop, вставка изображений, token-чип,
  MCP-probe, allowlist/токены, офлайн-npm, WebView2 preflight, single-instance —
  уже есть.
- Переключение модели/провайдера не требует рестарта движка: `providerID/modelID`
  передаются в каждом ходе. Рестарт — только при изменении определения провайдера.
- Ключ один на провайдера (endpoint + ключ); отдельных ключей на модели не бывает.
  Изоляция ключей между провайдерами не требуется: подключённые к движку ключи ему
  доступны.
- Локализация и доступность отложены, а не потеряны.
- Стоимость — оценка по ценам модели; фактическая стоимость из шлюза не нужна.
- Автоматический fallback между моделями/провайдерами — не требуется: переключение вручную.
- Политика артефактов в UI и предпросмотр дампов — не нужны; квоты/TTL в конфиге.
- PDF из чата сохраняется в inbox, но не читается: нужен экстрактор или PDF-режим модели.
- `.xlsx` читается постранично; даты остаются серийными числами, формулы — кэшированными значениями.
- `eco-pack --dry-run/--reproducible`, SBOM/provenance — сняты как оверинжиниринг.
